Hash Based Digital Signature Parameter Explorer

// context

Bitcoin authorizes spending with ECDSA and Schnorr signatures over the secp256k1 curve. Shor's algorithm would allow a sufficiently large quantum computer to solve the elliptic curve discrete logarithm problem and forge these signatures. Hash-based signature schemes rely only on properties of hash functions, which Bitcoin already depends on through SHA-256. Hash-based Signature Schemes for Bitcoin (Kudinov and Nick) surveys these schemes and their parameter selection for Bitcoin, and SHRINCS specifies a scheme that combines a stateful component with a stateless SLH-DSA (FIPS 205) component.

These schemes are assembled from a small set of building blocks: one-time signatures such as WOTS, few-time signatures such as FORS, and Merkle trees that combine them. Each exposes parameters. This site lets you adjust those parameters and see how they change signature size, public key size, signing and verification cost, statefulness, and signature budget, in terms of block space and transaction throughput. Figures can be cross-checked against the SPHINCS-Parameters scripts.

For each of the \(n\) message bits the signer holds two secret values, \(sk_{i,0}\) and \(sk_{i,1}\), and publishes their hashes as the public key. Signing reveals, for each bit \(m_i\), the secret value \(\boldsymbol{sk_{i,m_i}}\). The verifier hashes each revealed value and compares it with \(\boldsymbol{pk_{i,m_i}}\). All hashing uses a tweakable hash function \(\boldsymbol{\mathbf{Th}(P, (i, b), \cdot)}\), which binds each public key element to its position \((i, b)\) through a public parameter \(P\) and a tweak.

WOTS-TW signs an \(n\)-bit message with hash chains. The message is written as \(\mathrm{len}_1\) base-\(w\) digits \(b_i\), followed by the \(\mathrm{len}_2\) base-\(w\) digits of the checksum \(\boldsymbol{C = \sum_i (w - 1 - b_i)}\). Chain \(i\) starts at a secret value \(sk_i\) and applies \(\mathrm{Th}\) \(w - 1\) times to reach \(pk_i\). The signature reveals the value at position \(\boldsymbol{b_i}\) of each chain, and the verifier completes the remaining \(\boldsymbol{w - 1 - b_i}\) steps. Any other message has at least one digit lower than in the signed one, so a forgery needs a chain value earlier than the one revealed.

WOTS+C replaces the checksum chains of WOTS-TW with a search. The signer increments a counter until the digest \(\boldsymbol{d = \mathbf{Th}(P, T^*, m \,\|\, \mathbf{count})}\), written as \(\mathrm{len}_1\) base-\(w\) digits \(a_i\), has its first \(\boldsymbol{l = \mathbf{len}_1 - z}\) digits summing to \(\boldsymbol{S_{w,n}}\) and its last \(z\) digits equal to zero. The verifier checks both conditions, so the signature carries \(l\) chain values and the counter. Raising any digit forces another to fall, so a forgery on a new digest needs a chain value earlier than the one revealed.
