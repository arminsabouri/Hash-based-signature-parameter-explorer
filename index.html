Hash Based Digital Signature Parameter Explorer

// context

Bitcoin authorizes spending with ECDSA and Schnorr signatures over the secp256k1 curve. Shor's algorithm would allow a sufficiently large quantum computer to solve the elliptic curve discrete logarithm problem and forge these signatures. Hash-based signature schemes rely only on properties of hash functions, which Bitcoin already depends on through SHA-256. Hash-based Signature Schemes for Bitcoin (Kudinov and Nick) surveys these schemes and their parameter selection for Bitcoin, and SHRINCS specifies a scheme that combines a stateful component with a stateless SLH-DSA (FIPS 205) component.

These schemes are assembled from a small set of building blocks: one-time signatures such as WOTS, few-time signatures such as FORS, and Merkle trees that combine them. Each exposes parameters. This site lets you adjust those parameters and see how they change signature size, public key size, signing and verification cost, statefulness, and signature budget, in terms of block space and transaction throughput. Figures can be cross-checked against the SPHINCS-Parameters scripts.

For each of the \(n\) message bits the signer holds two secret values, \(sk_{i,0}\) and \(sk_{i,1}\), and publishes their hashes as the public key. Signing reveals, for each bit \(m_i\), the secret value \(\boldsymbol{sk_{i,m_i}}\). The verifier hashes each revealed value and compares it with \(\boldsymbol{pk_{i,m_i}}\). All hashing uses a tweakable hash function \(\boldsymbol{\mathbf{Th}(P, (i, b), \cdot)}\), which binds each public key element to its position \((i, b)\) through a public parameter \(P\) and a tweak.

WOTS signs an \(n\)-bit message with hash chains. The message is written as \(\mathrm{len}_1\) base-\(w\) digits \(b_i\), followed by the \(\mathrm{len}_2\) base-\(w\) digits of the checksum \(\boldsymbol{C = \sum_i (w - 1 - b_i)}\). Chain \(i\) starts at a secret value \(sk_i\) and applies \(\mathrm{Th}\) \(w - 1\) times to reach \(pk_i\). The signature reveals the value at position \(\boldsymbol{b_i}\) of each chain, and the verifier completes the remaining \(\boldsymbol{w - 1 - b_i}\) steps. Any other message has at least one digit lower than in the signed one, so a forgery needs a chain value earlier than the one revealed.

WOTS+C replaces the checksum chains of WOTS with a search. The signer increments a counter until the digest \(\boldsymbol{d = \mathbf{Th}(P, T^*, m \,\|\, \mathbf{count})}\), written as \(\mathrm{len}_1\) base-\(w\) digits \(a_i\), has its first \(\boldsymbol{l = \mathbf{len}_1 - z}\) digits summing to \(\boldsymbol{S_{w,n}}\) and its last \(z\) digits equal to zero. The verifier checks both conditions, so the signature carries \(l\) chain values and the counter. Raising any digit forces another to fall, so a forgery on a new digest needs a chain value earlier than the one revealed.

XMSS authenticates \(\boldsymbol{2^h}\) WOTS+C public keys as the leaves of a Merkle tree of height \(h\), and the root is the public key. To sign, the signer takes the next unused leaf \(i\), signs the randomized message digest with that leaf's WOTS+C key, and attaches the authentication path: the \(\boldsymbol{h}\) sibling nodes from the leaf to the root. The signature is \(\boldsymbol{(i, R, \sigma_{\mathbf{OTS}}, \mathbf{AuthPath}_i)}\). The verifier recomputes the leaf from \(\sigma_{\mathrm{OTS}}\), hashes up the path, and compares the result with the root. Each leaf signs once, so the signer keeps state: the index of the next unused leaf.

Each leaf is a WOTS+C public key: \(\mathrm{Th}\) compresses the ends of its \(l\) chains. Each inner node is \(\mathrm{Th}\) of its two children, and the root is the public key.

XMSSMT stacks \(\boldsymbol{d}\) layers of XMSS trees of height \(h'\) into a hypertree of total height \(\boldsymbol{h = d \cdot h'}\). The root of the top-layer tree is the public key. The root of each lower tree is signed by a WOTS+C key from the tree above it, and a bottom-layer WOTS+C key signs the randomized message digest. The signature holds the leaf index \(i\), the randomness \(R\), and for each layer \(\boldsymbol{(\sigma_{\mathbf{OTS}}, \mathbf{AuthPath})}\). The verifier recomputes each layer's root from the one below and compares the top-layer root with the public key. Each bottom-layer leaf signs once, so the signer keeps state: the index of the next unused leaf.

FXMSS is the stateful component of SHRINCS: a single Merkle tree of WOTS+C leaves whose structure the signer chooses at key generation, as a \(\boldsymbol{\mathbf{shape}}\) and a \(\boldsymbol{\mathbf{depth}}\). The verifier recomputes the root from the WOTS+C signature, the leaf position, and the authentication path, so it accepts any structure. In UXMSS the leaf for signature \(q\) sits at depth \(\min(q, \mathrm{depth})\), giving \(\boldsymbol{\mathrm{depth} + 1}\) signatures whose authentication paths grow by one node each. In BXMSS all \(\boldsymbol{2^{\mathrm{depth}}}\) leaves sit at the full depth. Each leaf signs once, so the signer keeps a state counter.

FORS (Forest of Random Subsets) is a few-time signature: \(\boldsymbol{k}\) Merkle trees of height \(\boldsymbol{a}\) whose leaves are secret values, with the public key a \(\mathrm{Th}\) of the \(k\) roots. The randomized message digest is split into \(k\) indices of \(a\) bits, and the signature reveals the indexed leaf of each tree with its authentication path. Each signature reveals \(k\) more leaves, so the probability of a forgery grows with the number of signatures \(\boldsymbol{q}\). FORS+C grinds a counter until the last tree's index is 0, which removes that tree's authentication path from the signature.

Visualization

Each tree has \(2^a\) secret leaves; the filled square is the leaf a signature reveals. The verifier hashes it up its authentication path to the tree's root and compresses the \(k\) roots into the public key.

SPHINCS+, standardized as SLH-DSA in FIPS 205, places a FORS key pair at every bottom-layer leaf of an XMSSMT hypertree. Signing hashes the message with randomness \(R\) into a digest that is split into the \(\boldsymbol{k}\) FORS indices, a tree index, and a leaf index. The selected leaf's FORS key signs the digest, the OTS key of that leaf signs the FORS public key, and each layer above signs the root below it, as in XMSSMT. The signature is \(\boldsymbol{(R, \sigma_{\mathbf{FORS}}, \sigma_{\mathbf{HT}})}\). Because the digest picks the leaf, the signer keeps no state, and the same FORS key pair can be selected more than once. The OTS is WOTS or WOTS+C, and the few-time signature is FORS or FORS+C.

Specification: SLH-DSA (FIPS 205)

SHRINCS combines two hash-based signature schemes under one public key, and a signature from either one passes verification. The stateful component is an FXMSS tree of WOTS+C leaves, which the signer uses as its primary path; the stateless component is SLH-DSA with a parameter set that is not among those standardized in FIPS 205, which the signer falls back to when signing state is unavailable. Each component contributes a root to the public key \(\boldsymbol{\mathrm{pk\_seed} \,\|\, \mathrm{sl\_root} \,\|\, \mathrm{sf\_root}}\), and the first byte of a signature, the indicator byte, tells the verifier which component signed.
